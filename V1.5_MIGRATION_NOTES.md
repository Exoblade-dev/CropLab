# CropLab v1.5 — Export Engine

## Scope

v1.5 upgrades export from a basic download action into a format-aware client-side export engine.

### Implemented

- Format registry for PNG, JPEG, and WebP.
- Browser capability detection prevents unsupported encoders from being offered.
- Format metadata separates:
  - MIME type
  - extension
  - quality support
  - transparency support
  - background support
- Quality is available only for JPEG and WebP.
- Quality range is 20%–100%.
- UI explicitly states that quality is not an exact file-size percentage.
- Output size is calculated from the actual browser-encoded Blob.
- Displays:
  - Original size
  - Estimated output size
  - percentage smaller/larger
- JPEG transparency handling through an explicit background color.
- Export dimensions remain format-independent.
- Export status states:
  - Preparing…
  - Cropping…
  - Resizing…
  - Encoding…
  - Downloading…
  - Complete
- WebP encoding status is explicitly shown as `Encoding WebP…`.
- Export preview is debounced to avoid encoding on every immediate control event.
- Export architecture is isolated so additional formats can be added through the format registry rather than rewriting the UI.
- Existing crop, resize, rotation, flip, zoom, history, upload, and local-only behavior are preserved.

## Technical basis

CropLab uses the browser Canvas `toBlob()` API for encoding. PNG is required by browsers; JPEG and WebP are offered only when the browser reports that their canvas encoder is available.

The output-size number is therefore an actual encoded Blob size for the current crop, dimensions, format, quality, and JPEG background settings. It is not derived from a percentage assumption.

## Verification

Run locally:

```powershell
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test
npm.cmd run build
```

Then perform browser QA with:
- PNG export
- JPEG export at 20%, 50%, and 100%
- WebP export at 20%, 50%, and 100%
- JPEG transparency/background handling
- Dimension changes
- Crop/rotation/flip combinations
- Large image export
- Download completion state
- Unsupported encoder behavior in a browser with limited format support

## Freeze criteria

v1.5 should be frozen only after:
1. Typecheck passes.
2. Lint has no errors.
3. Tests pass.
4. Production build passes.
5. Browser QA confirms exported files open correctly and match the selected settings.
6. Estimated output size matches the downloaded Blob size closely/exactly for the same settings.

## Intentionally not included

- PDF export
- AVIF export
- GIF/APNG export
- Server-side encoding
- Target-file-size compression
- Batch export
- Advanced encoder-specific controls
