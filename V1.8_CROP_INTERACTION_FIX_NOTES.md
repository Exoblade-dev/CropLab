# CropLab v1.8 — Crop Interaction Fix

## What the repo inspection found

The current main branch is `v1.8.3 (mobile ui patch v3)`. The mobile layout now gives the canvas the full remaining workspace, but the cropper's interaction layer is still relying entirely on react-easy-crop's injected absolute-positioning styles while the surrounding responsive layout is changing dimensions.

react-easy-crop documents that its Cropper fills the parent with an absolutely positioned container and handles mouse, touch, wheel, and keyboard interactions on that container. The patch makes that interaction surface explicit instead of depending on the injected defaults.

## Changes

- Explicitly make the react-easy-crop container fill the canvas stage.
- Explicitly keep the container in pointer hit-testing.
- Explicitly preserve `touch-action: none` for drag/pinch interaction.
- Add grab/grabbing cursor feedback.
- Set the mobile workspace grid to `width: 100%`, matching the manual width fix observed during browser QA.
- No App.tsx/editor-state changes.
- No export/history/image-engine changes.
