# CropLab v1.9 — Performance Architecture

## Scope

v1.9 begins the performance architecture work by measuring expensive image operations before introducing workers or OffscreenCanvas. It also adds a small set of product-level interaction improvements requested during the large-image validation pass.

## Performance measurement foundation

- Added browser Performance API measurements around image loading and decoding.
- Added measurements for GIF first-frame materialization, including canvas draw and PNG encoding.
- Added measurements for export canvas drawing and browser encoding.
- Added optional long-task observation when diagnostics are enabled.
- Diagnostics can be enabled with `?perf=1` or the `croplab-performance` local-storage flag.
- No Worker or OffscreenCanvas path is added yet.
- The purpose of this phase is to identify whether loading, canvas drawing, encoding, repeated preview work, or main-thread blocking is the actual bottleneck.

## Large-image safety ceiling

- Increased the decoded image pixel ceiling from 40,000,000 to 50,000,000 pixels.
- The existing 50 MB input-file limit remains unchanged.
- The existing 8192 px maximum source dimension remains unchanged.
- The intended stress case is now allowed through validation:
  - 8064 × 6048
  - 48,771,072 pixels
- Oversized panoramas such as 11111 × 5147 remain rejected because their source dimension exceeds the current 8192 px safety boundary.
- Very large files such as 230 MB remain rejected by the existing 50 MB file-size boundary.

## Shortcut guide

- Added a persistent `Shortcuts` control to the application header.
- Added a modal guide covering the currently supported editor shortcuts:
  - Ctrl/Cmd + Z — Undo
  - Ctrl/Cmd + Shift + Z — Redo
  - R — Rotate 90° right
  - 0 — Fit view
  - 1 — Zoom to 100%
  - 2 — Zoom to 200%
  - + / = — Zoom in
  - - — Zoom out
  - Esc — Exit the active tool / close an open editor surface
  - Ctrl/Cmd + O — Open or replace an image
  - Ctrl/Cmd + S — Export
- The guide explicitly notes that shortcuts are ignored while editing form controls.

## Home navigation

- The CropLab wordmark in the application header is now an explicit home action.
- When an image is loaded, returning home uses the same destructive confirmation model and clears the current image/edits before returning to the upload/hero screen.
- When no image is loaded, the action simply returns to the top of the home/upload surface.

## Confirmation dialogs

- Replaced native browser `window.confirm()` prompts for destructive editor actions with a CropLab-styled confirmation dialog.
- Applied to:
  - Replace image
  - Clear current image
  - Reset edits
  - Return home while an image is loaded
- Destructive confirmation actions use a red primary button to make the consequence visually clear.
- Dialogs provide keyboard dismissal, labelled dialog semantics, and contained focus behavior.

## Freeze

v1.9 is not frozen. This is the measurement and large-image stress-test phase.

## Large-image interaction optimization pass

Final v1.9 performance work for the 8064 × 6048 stress case:

- Added a 4096 px maximum working-resolution preview for oversized source images.
- Kept the original decoded image as the authoritative export source.
- Mapped crop coordinates from the working preview back to original source pixels.
- Used `createImageBitmap()` resizing when available, with a safe fallback path.
- Added preview-generation performance measurement.
- Preserved the existing export engine and output-resolution behavior.
- Added regression tests for preview sizing and crop-coordinate conversion.
- No Worker or OffscreenCanvas implementation was added because the optimization can reduce interactive raster workload without changing the editor architecture.

The 8064 × 6048 stress test remains the final validation target before v1.9 is frozen.

## Export regression fix

The first working-preview pass exposed a new export regression during browser testing: export time could increase because the automatic encoded-size preview and the manual download could perform overlapping encoding work.

This pass fixes that without changing the export engine:

- Increased the automatic encoded-size preview debounce to 1000 ms so active editing is less likely to trigger an expensive encode immediately before download.
- Reuse the already encoded preview Blob when its crop, transform, format, quality, dimensions, and background settings exactly match the requested download.
- Fall back to the existing full-resolution export path when no matching preview Blob is available.
- Preserve original-resolution export and source-pixel crop mapping.
- No Worker or OffscreenCanvas dependency added.

The performance target is now: reduce unnecessary duplicate encoding while preserving the existing export result exactly.
