# v1.11 — Input foundation

## Input normalization

- File picker accepts multiple images while preserving selection order.
- Drag-and-drop accepts multiple images while preserving drop order.
- Clipboard paste collects image items through the same input path.
- Picker, drop, and clipboard inputs normalize to a shared `ImageInputResult` contract.
- Every candidate file passes the existing signature/MIME/size validation before entering the editor.
- Invalid files are surfaced instead of being silently ignored.
- Browser navigation caused by dropping files on the page is prevented.

## Phase boundary

Phase 5 establishes the input boundary as `Input → File[]`.

The current editor remains single-image: when multiple valid files arrive, the first file is opened and the user is told that batch editing is handled by Phase 6. No image collection, thumbnail rail, switching, batch processing, or ZIP export is introduced here.
