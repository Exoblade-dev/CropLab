# v1.12 — Image Collection & Batch Export

## Goal

Turn Phase 5's normalized `File[]` input into a browser-local image collection without moving batch behavior into the individual editor pipeline.

## Implemented

- Added `useImageCollection` for source files, thumbnail object URLs, active image identity, and per-image editor history.
- Added image switching with restoration of each image's editing state.
- Added a right-side thumbnail rail with collection count and add-images control.
- Added current-image removal without clearing the rest of the collection.
- Extended replacement so the first selected file replaces the active image and additional files are added to the collection.
- Added sequential batch export through the existing full-quality Canvas export pipeline.
- Added a browser-local ZIP writer with UTF-8 filename support and stored entries.
- Added batch progress and cancellation controls.
- Added Phase 6 architecture and ZIP regression tests.

## Export model

Each collection item keeps its own editor history. Batch export uses the current snapshot for each image, loads that source independently, runs the same export geometry and adjustment pipeline used by individual exports, then packages the resulting encoded files into one ZIP archive.

No backend, upload service, worker, or new runtime dependency was introduced.

## Verification

Static TypeScript syntax checks were run on the changed `.ts` files using Node's built-in type stripping. The ZIP writer was executed directly and verified to produce valid local-file, central-directory, and end-of-central-directory signatures for multiple entries.

Full `npm test`, `npm run lint`, and `npm run build` could not be executed in the build environment because the project dependencies were not installed and the dependency installation attempt timed out.
