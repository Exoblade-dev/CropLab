# CropLab v1.6 — Reliability & Image Handling

## Image loading
- Local files use `URL.createObjectURL()` instead of base64/Data URLs.
- Object URLs are revoked on replacement, clearing, and unmount.
- Stale async loads cannot overwrite newer selections.
- Images are decoded before entering the editor.

## Validation
- 50 MB file-size limit retained.
- Actual signatures validated for JPEG, PNG, WebP, and GIF.
- Unsupported MIME types and MIME/signature mismatches rejected.
- Decoded dimensions validated.
- Safe dimension and pixel-count limits enforced.
- Empty and malformed images rejected explicitly.

## GIF
- GIF input accepted.
- CropLab edits the first/static frame.
- Exports remain static PNG, JPEG, or WebP; animation is not preserved.

## Transparency
- Checkerboard preview retained.
- PNG/WebP preserve transparent pixels.
- JPEG uses configured background because JPEG has no alpha.

## Verification
Typecheck, lint, tests, build, and browser QA covered valid/malformed files, GIFs, large images, MIME/signature mismatches, transparent images, and JPEG backgrounds.

## Freeze
v1.6 established the reliability and image-handling baseline.
