# CropLab v1.8 repair

## Root cause

The v1.8 commit replaced `src/App.css` instead of extending it. The original v1.7/v1.4 base stylesheet contained the application variables, workspace layout, canvas, upload screen, export panel, toolbar, footer, and core responsive rules. The broken file contained only the new v1.8 mobile/accessibility additions. This caused the browser to render most of CropLab with default HTML styles.

## Repair

- Restored the exact v1.7 base `src/App.css` and appended the v1.8 mobile/accessibility layer.
- Preserved the v1.8 dedicated mobile interaction model.
- Improved mobile rotate controls with explicit left/right accessible names.
- No editor, export engine, image-loading, history engine, or desktop component logic was changed.

## Verification

The repair should be applied over the current v1.8 repository. Run the normal typecheck, lint, tests, build, and browser QA before considering v1.8 fixed/frozen.
