# CropLab v1.6 Migration Notes

## Scope

v1.6 hardens image loading and validation for reliability with large, malformed, spoofed, and GIF inputs.

## Image loading

- Load local files through `URL.createObjectURL()` rather than converting the source file into a base64/Data URL.
- Revoke object URLs when replacing, clearing, or unmounting the image loader.
- Guard against stale asynchronous loads overwriting a newer image selection.
- Decode the loaded image before exposing it to the editor.

## Validation

- Keep the 50 MB file-size limit.
- Validate the file's actual image signature for JPEG, PNG, WebP, and GIF.
- Reject unsupported MIME types and MIME/signature mismatches.
- Validate decoded dimensions before opening the editor.
- Enforce safe dimension and pixel-count limits to avoid browser canvas failures and excessive memory use.
- Reject empty and malformed images with explicit errors.

## GIF behavior

GIF input is accepted as an input format, but CropLab edits the first/static frame exposed by the browser image decoder. Exports remain static PNG, JPEG, or WebP images; animation is not preserved.

## Transparency

The editor canvas retains its checkerboard transparency preview. PNG and WebP can preserve transparent pixels. JPEG exports use the configured background color because JPEG has no alpha channel.

## Verification

Run typecheck, lint, tests, and a production build locally. Browser QA should include valid and malformed files, GIF input, large images near the limits, MIME/signature mismatches, transparent PNG/WebP, and JPEG exports with white, black, and custom backgrounds.
